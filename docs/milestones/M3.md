## M3-A — COMPLETE

## Implementation

`JudgePort` accepts only `rubric`, `currentAnswer`, structured
`priorConfirmedState`, and optional `lastGuidance`. `OpenAIJudgeAdapter` uses one
stateless Responses API classification with no tools, browsing, files, memory, or
conversation state. The Responses API request explicitly sets `store: false`
(the provider default is not trusted), disables SDK retries, and supplies no
custom logger. The SDK client explicitly sets `logLevel: "off"`, so an external
`OPENAI_LOG` value cannot enable request/response logging for Judge traffic. A
deterministic adapter test locks these request/client properties. The SDK is isolated to
`src/adapters/openai-judge`; domain/application code contains no vendor import.

The output vocabulary is `AnswerType`, `Ambiguity`, and one `NodeStatus` per rubric
node. `DISCOVERED`, `PARTIAL`, and `CONTRADICTED` require one nonempty evidence
string copied from a unique literal occurrence of the exact current answer.
`ABSENT` requires null evidence. Application validation rejects missing, duplicate,
or unknown nodes, invalid status/evidence combinations, fabricated evidence, and
ambiguous duplicate occurrences, then discards the literal and produces canonical
`answer_id` plus UTF-16 `span_start`/`span_end`. Stored answers are never normalized.

The semantic prompt is immutable under `judge-v1`. A semantic change requires a new
identifier and evaluation rerun. It tells the classifier to consider only current
answer evidence, accept conceptual paraphrase without terminology, ignore
eloquence, prefer precision, treat uncertainty conservatively, distinguish active
contradiction from rejected quotations, and never infer hidden identity or decide
game policy.

## Configuration and runtime modes

All values are server-only; there are no `NEXT_PUBLIC_OPENAI_*` variables.

```text
JUDGE_ADAPTER=fake
JUDGE_ADAPTER=openai
OPENAI_API_KEY=...
PRIMARY_JUDGE_MODEL=<explicit candidate>
ADJUDICATION_MODEL=<reserved; unused by gameplay>
REVEAL_COMPARISON_MODEL=<reserved; unused by gameplay>
```

Fake mode is the deterministic local/CI/E2E default. Neither browser input nor an
HTTP parameter can select provider or model.

## Retry, failure, and EVALUATING recovery

OpenAI SDK automatic retries are disabled. One retry is permitted only for
transport, structured-schema, node-set, or literal-evidence failure. Valid semantic
output never retries. Two failures produce only `JUDGE_UNAVAILABLE` (HTTP 503); raw
provider messages, prompt, rubric, hidden state, and response body are not returned.

The store first reserves answer + `EVALUATING` using the expected state version.
The provider call runs without an open PostgreSQL transaction. Success validates
and deterministically merges in another transaction. Failure removes the reserved
answer and restores the prior `THINKING` state without consuming a turn, while
advancing `state_version`. Reload/retry is therefore safe within M3 scope.

## Migration and observability

`202609080005_m3_ai_runs.sql` creates forward-only `ai_runs`. It records run ID,
nullable session/answer, purpose, provider, model, prompt/content/dataset versions,
attempt, schema validity, status, nullable token/cost/request ID, latency, and
injected creation time. It has no columns for prompt, response, user answer, or
literal evidence. Failed reservation deletion nulls its answer reference. No Sentry
integration or SDK debug logging is configured. Application errors carry only
identifiers/status categories; generated eval reports are checked before writing
to reject raw-answer and raw-payload fields.

## Gold dataset and metrics

`eval/judge/v1` contains `judge-gold-v1`: 20 individually authored seed JSONL cases
and 26 manually labelled adversarial groups with four reviewed surface variants
each (104 messy cases; 124 total). It covers full/partial/absent/contradicted nodes,
all answer types and ambiguity modes, Korean colloquial language, grammar mistakes,
Unicode, spacing, long answers, negation and double negation, quotations,
self-correction, unclear references, keyword stuffing, theory-name-only answers,
wrong causal direction, and structured prior state.

`pnpm eval:judge` requires explicit `OPENAI_API_KEY` and `PRIMARY_JUDGE_MODEL`, emits
a redacted JSON report under gitignored `artifacts/eval/judge/`, and prints a concise
summary. Reports include git SHA, dataset/content/model/prompt identity, case count,
per-status and per-node precision/recall/F1, macro F1, core DISCOVERED
precision/recall with numerators/denominators, confusion tables, evidence counts,
provider/schema failures, retries, latency percentiles, tokens, optional cost, and
failure case IDs. Critical lock eligibility merges structured prior state with the
current expected/predicted statuses using the same pure semantic-state helper as
the deterministic game policy. Eligibility requires the configured number of
required DISCOVERED nodes and no blocking CONTRADICTED node. Premature-lock cases
are those whose expected merged state is ineligible while the predicted merged
state is eligible; premature-unlock cases are the inverse. Rescue/max-turn behavior
is deliberately excluded from this Judge semantic proxy.

## M3-B1 — Judge v2 semantic calibration

`judge-v2` separates conceptual completeness from confidence and ambiguity.
DISCOVERED requires the complete proposition but does not require certainty;
PARTIAL is reserved for structural incompleteness. AnswerType, Ambiguity, current
answer evidence, rejected claims, self-correction, and prior-state limits are
defined in [`judge-v2-semantic-contract.md`](../evals/judge-v2-semantic-contract.md).

`conway-law` version 2 retains PUBLIC_PLAY, SERVER_POLICY, and REVEAL_CONTENT and
sharpens only JUDGE_RUBRIC. It is not scheduled; production continues to resolve
version 1. `eval/judge/v2` defines `judge-dev-v2` as a versioned delta over the
unchanged 124 v1 texts. Every changed label verifies its prior value and records a
semantic rationale in both the machine ledger and
[`judge-v2-label-audit.md`](../evals/judge-v2-label-audit.md).

The same OpenAI adapter supports explicit immutable prompt versions. Its default is
still `judge-v1`; the composition root passes no override. The eval suite defaults
to `v1`, while `JUDGE_EVAL_SUITE=v2` loads the v2 manifest, content version 2, and
`judge-v2`. Unsupported prompts, prompt/manifest mismatch, stale label overrides,
and content identity mismatch fail before provider execution.

## M3-B2 — Judge v3 semantic and operational calibration

`judge-v3`, `conway-law` v3, and `judge-dev-v3` are explicit development-only
identities. V3 makes reverse causal direction part of SYSTEM_RESEMBLANCE, broadens
COMMUNICATION_FRICTION to semantic communication-defined groupings, narrows
DECISION_CLUSTERING to actual local decision/design partitioning, and hardens EMPTY
and CONFLICTING_CLAIMS. The audited five-field label delta and unchanged-case review
are in [`judge-v3-semantic-contract.md`](../evals/judge-v3-semantic-contract.md).

The evaluator recursively resolves the confined chain `v3 → v2 → v1`, rejects
cycles and stale overrides, and aggregates redacted schema/evidence failure classes.
The same category can be stored internally in `ai_runs`; external failures remain
`JUDGE_UNAVAILABLE`. The v3 system prompt is deterministically required to be at
least 15% smaller than v2 while content thresholds live in JUDGE_RUBRIC.

No live OpenAI call occurs in M3-B2 or CI. No final holdout is created, no Terra run
is performed, and no M4 work is included. Runtime and Daily remain on v1.
