## M5-A — Reveal Outcome Foundation — COMPLETE

A pure domain resolver derives the following outcome from existing persisted
adaptive session facts, with zero provider calls and no score or percentage:

| Code | Korean label | Neutral explanation |
| --- | --- | --- |
| INDEPENDENT_REDISCOVERY | 독립 재발견 | 핵심 관계를 힌트 전에 스스로 연결했습니다. |
| GUIDED_ARRIVAL | 힌트 후 도달 | 단서를 바탕으로 핵심 관계까지 연결했습니다. |
| PARTIAL_CAPTURE | 핵심 일부 포착 | 중요한 요소들을 스스로 발견했습니다. |
| REVEAL_CONNECTION | Reveal에서 연결 | 이번에는 Reveal을 통해 새로운 연결을 만납니다. |

Derivation precedence:

1. Turn 1 COMPLETE_LIKELY → INDEPENDENT_REDISCOVERY, even though the required
   CONSOLIDATE prompt and second reasoning turn still follow.
2. Otherwise final merged learner state COMPLETE_LIKELY → GUIDED_ARRIVAL. This
   reuses the existing required-node/blocking-node/lock-threshold resolver.
3. Otherwise at least one required node DISCOVERED, or at least two distinct
   required nodes PARTIAL → PARTIAL_CAPTURE. Optional nodes do not qualify;
   a misconception does not erase genuine progress on other required nodes.
4. Otherwise → REVEAL_CONNECTION, a neutral new connection rather than failure.

### Turn 1 provenance and persistence

M4 already atomically persists the first adaptive guidance decision as
`adaptive-v1:1:<learner-state>:<action>:<target>`. Its state is calculated after
Turn 1 semantic merge, before Turn 2; COMPLETE_LIKELY maps to CONSOLIDATE with
empty target. Turn 2 writes a separate key and does not replace this event.
Existing PostgreSQL reload retains the key while reconstructing approved text.
The outcome uses the validated key, not mutable guidance wording or the final
merged state as a lossy Turn 1 proxy. Exactly one valid Turn 1 key and two turns
are required for adaptive outcome derivation; missing/ambiguous/invalid provenance
raises an explicit error rather than fabricating independence.

No new snapshot, column, table, DB migration, or provider port is required.
M4's outstanding local DB migration/persistence check remains mandatory before M9;
this provider-free gate neither applies migrations nor claims DB/hosted validation.

### Public boundary

Only the existing authorized `reveal` application result adds
`revealOutcome: { code, label, explanation }` for adaptive content. Authorization
(owned session, LOCKED/REVEAL_READY/REVEALED) occurs before derivation or hidden
content loading. Play/start/getOwned projections do not gain an outcome.
Legacy/nonadaptive Reveal omits the new field and retains discoveryOutcome,
representative-thought and connection behavior. The historical verifier's
discoveryOutcome is not reinterpreted as an achievement or overwritten.

No UI rendering, numerical score, new correctness claim, animation, personalized
comparison, history/streak/account/analytics feature, LLM prose, or v6 scheduling
was added. Conway v6 remains UNSCHEDULED; Final Synthesis research is untouched.
