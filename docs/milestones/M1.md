# M1 — Deterministic Walking Skeleton

Date: 2026-09-08 (Asia/Seoul)

Status: implemented; contradiction-integrity closure is locally and host-CI accepted.
Canonical authority remains G1 Master Codex Handoff Packet v1.

## Repository-review acceptance closure

The final M1 repository review found and closed three implementation defects
before M2 began:

1. FakeJudge classification had trimmed the submitted answer before constructing
   evidence offsets. Classification still uses a trimmed copy, while evidence now
   records the leading-whitespace start and trailing-whitespace end in the exact
   original string stored as the submitted thought. Regression coverage preserves
   the original text and resolves its representative evidence without offset drift.
2. The Result client had completed a `LOCKED` session itself. Result now replaces
   that route with `/reveal/[session]`; only `REVEALED` renders Result, and every
   pre-Lock status returns to Play. The Reveal screen remains the sole owner of the
   staged animation and Reveal-completion action.
3. The turn indicator had added one to the submitted count unconditionally. It now
   derives progress from the authoritative public session `turnCount`, `status`,
   and application-projected M1 maximum. Initial Play announces the first thought
   in progress, while Rescue/Lockable announces two submitted thoughts and displays
   `2 / 2`, never `0 / 2` or `3 / 2`.

## Final contradiction-integrity closure

A final audit found that the ordinary maximum-turn Rescue check ran before the
blocking-contradiction check. A misconception introduced on turn two could
therefore reach `RESCUE` and `LOCKABLE` while its node remained contradicted.

The deterministic M1 rule is now:

- an active `CONTRADICTED` node always selects `CORRECTION` before the ordinary
  maximum-turn Rescue rule;
- at the normal turn limit the session remains `THINKING / CORRECTION`, exposes no
  Lock action, and accepts no additional thought;
- the user can explicitly continue without rewriting through one corrective
  Rescue action; that action appends a `RESCUE` guidance event and resolves only
  the policy block, then moves the session to `LOCKABLE`;
- the node remains `CONTRADICTED`, with its literal evidence, so Judge history is
  not rewritten as discovery or partial understanding;
- Lock independently rejects any session whose contradiction policy block is
  still unresolved.

This is bounded by the normal two submitted thoughts plus a single deterministic
recovery action. Snapshot reconstruction reapplies the same explicit corrective
Rescue when reconstructing a legitimately locked or revealed public snapshot.

The M1 Judge evidence contract now requires valid current-answer evidence for
`DISCOVERED`, `PARTIAL`, and `CONTRADICTED`; only `ABSENT` omits it. FakeJudge maps
misconception evidence into the exact original-answer coordinates, including
leading and trailing whitespace. `NodeDiscovery.contradictionEvidence` preserves
that answer/span reference separately from discovery evidence. The HTTP schema
validates non-blank input without trimming the canonical submitted string.

## Implemented

A complete Conway fixture flow runs in the browser:

```text
Home → Scenario / Thinking → Evaluating → Guidance when needed
     → Lockable → explicit Lock → staged Reveal → Result
```

The interface uses an editorial scenario card, thought composer, guidance card,
collapsed previous thoughts, evidence Lock panel, and staged historical Reveal.
It has no chat bubbles, assistant persona, score, failure state, or login prompt.

## State model and policy

`PlaySession` contains the M1 minimum: ID, PRACTICE attempt type, canonical status
and stage, turn count, submitted thoughts, confirmed node discoveries, guidance
events, evidence span reference, and Reveal completion flag.

All mutations are pure domain transitions invoked by application use cases. The UI
cannot promote a session. M1 uses two configurable turns:

- sufficient discovery including system resemblance and no active contradiction →
  `LOCKABLE` immediately;
- partial discovery on turn one → prewritten `REFLECT`;
- absent reasoning on turn one → prewritten `NUDGE`;
- blocking misconception on turn one → prewritten `CORRECTION`;
- unresolved non-contradictory turn two → prewritten `RESCUE` and `LOCKABLE` with
  guidance;
- active contradiction → `CORRECTION` before turn-limit handling, followed at the
  limit by an explicit bounded corrective Rescue before `LOCKABLE`;
- only explicit Lock → `LOCKED`; only the Reveal completion action → `REVEALED`.

Delivered guidance text is not repeated. Previously discovered node status and
first discovery stage are preserved. Representative evidence prefers confirmed
discovery evidence, otherwise the latest non-empty actual thought. Evidence is an
answer ID plus literal span, not a rewritten answer.

## FakeJudge

`JudgePort` receives current answer, prior confirmed state, and optional last
guidance with no provider/network/prompt types. `FakeJudgeAdapter` deterministically
recognizes fixture wording for FULL_DISCOVERY, PARTIAL_DISCOVERY, WRONG_OR_ABSENT,
and MISCONCEPTION, returning structured node results and literal evidence spans.
It never selects guidance, Lock, or Reveal.

## Persistence and resume

`InMemoryPrimaryStore` is the authoritative M1 application adapter. It survives a
normal browser reload while the server process lives. A temporary M1-only
`localStorage` snapshot stores session ID, actual thought strings, and public status;
it stores no Reveal fixture or internal node result. If memory is missing, the
server reconstructs authoritative state by replaying those thoughts through the
same Judge and policy, then reapplies permitted Lock/Reveal actions. M2 replaces
this bridge with persistent server state. It is not anonymous identity semantics.

## Routes and secret boundary

Browser routes: `/`, `/play/[session]`, `/reveal/[session]`, `/result/[session]`.
M1-only route handlers under `/api/demo/sessions` expose the explicit start, get,
restore, submit, corrective recovery, Lock, Reveal-read, and Reveal-complete use
cases. They are not the production M2 Daily API contract.

The public content and hidden node structure do not contain historical attribution.
The server-only Reveal fixture contains 1968, Melvin Conway, Conway's Law, and its
explanation. The Reveal API rejects requests before `LOCKED`. Initial HTML and
pre-Lock demo API responses are tested to exclude those strings.

## Reveal and accessibility

Timing is centralized in `REVEAL_TIMING_MS`: normal staging totals about 3 seconds;
reduced motion uses the same information order in roughly 200 milliseconds and
never controls completion authority. The sequence is representative thought,
rewind, year, person, theory, then connection. Result includes deterministic
personalized comparison and whether Rescue/Correction was used.

Touch actions are at least 48px; textarea font is 16px; mobile overflow and primary
action access are tested. Semantic heading/order, collapsed history, live status,
keyboard-native controls, and reduced motion behavior form the M1 accessibility
baseline.

## Known limitations and M2 handoff

- Process restart or multi-instance deployment loses in-memory state; local replay
  is a demo recovery bridge and has no production integrity/security claim.
- FakeJudge is intentionally narrow keyword classification, not language quality.
- Conway is a single code fixture; there is no content schema, approval, versioning,
  schedule, or publication pipeline.
- M1 has no concurrency control, nonce, idempotency, quotas, auth, analytics, AI,
  database, Redis, external API, or production identity.
- M2 introduces canonical Daily/content persistence and anonymous device behavior;
  it must preserve the port boundary and replace temporary storage without moving
  authority into the client.

No M2 or later functionality is implemented. M2 must not start automatically.
